# v1.3 UI refactor and branch cleanup

Status: In progress — Phase A completed

Date: 2026-08-28

## Baseline

- Public release: `v1.2.0`.
- Release commit: `90f05d0`.
- `main` integration commit: `7eda835` (PR #8).
- Supported channels: Windows stable and Linux beta.
- macOS remains deferred.
- Quick Panel and RGBIC remain outside the public stable surface.

No v1.3 work starts from an old feature branch. The implementation baseline is
the updated `main` after repository cleanup.

## Objectives

1. Reduce the repository to a small, understandable branch set without losing
   experimental history.
2. Refactor the shared Windows/Linux UI into a consistent, accessible and
   responsive desktop experience.
3. Preserve the validated LAN control, targeting, persistence, tray and build
   paths from v1.2.0.
4. Keep experimental Quick Panel and RGBIC work isolated from the public
   v1.3 UI branch.

## Phase B — v1.3 UI foundation

Create `feature/v1.3.0-ui-foundation` from the updated `main`.

The detailed design-first workflow, Qt Quick/QML migration, acceptance gates and
cross-platform verification matrix are defined in
`docs/codex/plans/2026-08-28-v1.3-ui-design-execution-plan.md`. That document
is the implementation playbook for Phases B through F.

Deliverables:

- define shared spacing, typography, surface, focus and state tokens;
- prove the PySide6 + Qt Quick/QML shell before migrating public panels;
- establish reusable accessible buttons, cards, section headers and feedback
  states;
- retain one responsive component tree for Windows and Linux;
- add compact, regular and wide layout tests;
- preserve English/Spanish runtime switching and the hardcoded-string audit.

This phase changes presentation primitives, not LAN protocol, discovery,
targeting semantics or persistence formats.

## Phase C — navigation and targeting experience

- make device selection visible and immediately responsive on Home;
- support one, several or all lights without persistent group editing;
- expose selection, online state and mixed capability state clearly;
- make keyboard focus and disabled states understandable;
- validate with `WIZZ_DEV_VIRTUAL_BULBS` plus the real single WiZ light;
- avoid coupling selection repaint to scene or device polling updates.

## Phase D — primary panels

Refactor incrementally, in this order:

1. Home and target selector.
2. Color Studio and white temperature controls.
3. Scenes and Favorites.
4. Routines and Settings.
5. Hotkeys presentation, including the intentional Linux unavailable state.

Each panel must keep its existing behavior tests while adding focused visual
state and accessibility tests. A panel is not migrated by copying experimental
Quick Panel code.

## Phase E — responsiveness and resource use

- coalesce rapid slider updates without delaying direct button actions;
- refresh only controls whose state changed;
- use an adaptive low-frequency idle poll and bounded active refresh;
- measure startup, idle CPU/memory and interaction latency on packaged builds;
- prevent simulated dynamic scenes from being treated as evidence of physical
  fade timing;
- preserve one `LightController` and one command path.

Performance targets will be recorded from a baseline before implementation;
the plan does not invent numeric promises without measurements.

## Phase F — release validation

- full automated suite and i18n audit on Windows and Ubuntu;
- virtual multi-device targeting matrix;
- real WiZ smoke for power, brightness, RGB, Kelvin and scenes;
- packaged Windows and Linux UI smoke at supported window sizes;
- tray, persistence, launcher, autostart and update-check regression;
- accessibility review for keyboard focus, disabled state and contrast;
- clean build from the same approved release commit on both platforms.

## Parallel experimental channel

RGBIC closed-beta work may continue only on a new branch created from current
`main`, such as `beta/v1.3.0-rgbic-hardware-validation`. It must not be merged
into the UI foundation until its protocol, capability detection and hardware
evidence meet a separately documented gate.

Quick Panel remains paused. Reconsidering it requires a new architecture
decision for a true temporary window and focus lifecycle; it is not part of
the first v1.3 UI milestones.

## Definition of done

- branch inventory is reduced and archived history remains reachable;
- `main` and project context describe v1.2.0 accurately;
- v1.3 UI work is based on current `main` and isolated from experiments;
- primary flows are visually consistent and keyboard-accessible;
- no regression in LAN control, targeting, persistence or packaging;
- both platform artifacts pass automated and manual release gates.
